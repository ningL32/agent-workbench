# BRAINSTORM · 任务雷达（钉钉听记 → AI 拆解 → 任务收件箱）

> 状态：头脑风暴 v2（2026-10-18）· 业主已拍板：MVP 先钉钉 / 钉钉 CLI 已打通 / v1 一律过确认闸门
> 原则：AI 提议，人决策；溯源一等公民；本机 CLI 做分析引擎，不直连 LLM API

## 一、场景与端到端旅程（MVP）

1. 会议/面谈 → 钉钉「听记」生成纪要（带说话人分段）
2. 业主在指挥台点「同步」→ dingtalk-minutes 通道拉取新纪要 → 消息池（增量，按内容哈希去重）
3. 拉取完自动逐条 AI 分析（后台，进度可见）→ 候选任务卡进「任务收件箱」
4. 业主在收件箱：逐张或批量 确认入库 / 编辑后入库 / 拒绝；确认时可勾选「记住此说话人映射」
5. 入库任务卡带溯源（源/说话人/原文引用）；收件箱持久统计确认/拒绝比例 = 误识率仪表

## 二、数据源锁定（MVP 只接一个）

**钉钉听记/纪要（dingtalk-minutes 通道）**，不接 dingtalk-chat。理由：
- 听记是业主团队最高频的记录方式（已确认）
- 纪要天然带说话人分段 → 负责人归因有据可依
- 会议/面谈内容任务密度高；群聊噪声大且授权复杂（二期再评估）

## 三、统一消息模型（关键抽象）

```json
{
  "id": "msg-<hash>",              // 内容哈希，幂等锚点
  "source": "dingtalk",
  "kind": "minutes",               // minutes | chat | todo（后续扩展）
  "title": "周三需求对齐会",
  "speakerSegments": [             // 说话人分段（纪要原生结构）
    { "raw": "建国", "memberId": null, "text": "SSO 这块周五前要上线", "at": "..." }
  ],
  "content": "全文文本",
  "occurredAt": "ISO8601",
  "ref": { "dingtalkId": "...", "url": "..." },
  "contentHash": "...",
  "analyzedAt": null               // 分析水位：null=待分析
}
```

## 四、AI 分析管线（每条纪要一个分析单元）

输入三件套：①纪要全文（带说话人分段）②成员名册快照（别名+姓名，供"让小王去做"归人）③**当前看板任务清单**（title+status——防重复建卡的关键，AI 先查重再提议）

输出 JSON schema（spawn `claude -p` 结构化输出，解析失败重试一次）：

```json
{ "tasks": [{
    "title": "", "desc": "", "priority": "high|medium|low|unset",
    "suggestedMemberId": "", "dueHint": "周五",   // 原文日期词，不强行转日期
    "confidence": 0.0,                             // 见下方规则
    "quote": "原文那句话", "rationale": "为什么这是任务"
  }],
  "noise": [ { "quote": "", "reason": "" } ]       // 判为非任务的部分也留痕
}
```

置信度规则（写死在 prompt，可复核）：
- 0.9+：明确动作 + 明确负责人 + 明确时间
- 0.7~0.9：明确动作，负责人或时间模糊
- 0.5~0.7：推断性（"这个后面得弄"）
- <0.5：不产出候选（进 noise）
- few-shot 正反例：寒暄✗、"我看看"✗、"周五前给我"✓、"@小王 把部署文档更新下"✓

拆解规则：单条纪要候选 ≤10 张，超出按置信度截断；v1 拍平不建父子层级；一条消息多任务逐张出；跨消息任务（上下文分两条说的）v1 不合并，靠人确认时改 desc。

## 五、任务收件箱（人工闸门 = 也是误识率仪表）

- 侧栏新视图「收件箱」，徽标显待确认数；候选卡按置信度降序
- 候选卡：标题（可编辑）/ 置信度徽标 / 建议负责人（下拉，预填映射结果）/ dueHint（显示原文词"周五"+ 日期选择器落具体日）/ 优先级 / 原文引用（折叠，含源+说话人+原句）
- 操作：确认入库 / 编辑后确认 / 拒绝；批量全选→确认/拒绝
- **误识率仪表**：每批次 confirmed/rejected 持久化，收件箱头部显示近 30 天拒绝率——"跑一个月看误识率"的度量落点，数据从第一天就开始攒
- 入库映射：候选卡 → POST /api/tasks，task 新增 `origin` 字段 `{type:"inbox", refId, quote}`（溯源落点）

## 六、说话人映射（MVP 最小闭环）

- members.json 成员新增 `aliases: []`（钉钉昵称数组）
- 分析时：说话人 raw → 精确匹配 aliases/name → 命中填 suggestedMemberId；未命中留空显示原始名
- 确认卡时提供「记住此映射：建国 → 王建国」勾选 → POST /api/members/:id/aliases，下次自动归人

## 八、风险与边界

- 图片消息/白板内容 v1 不处理（纪要里通常是文字段）；撤回消息不追
- 分析耗时秒~十秒级/条，按条异步、进度条可见；CLI 超时 120s 重试一次
- 隐私：消息池落盘 data/（本地），同步范围由业主在钉钉侧授权决定
- 去重两道防线：内容哈希（同一纪要重复同步）+ AI 查重（同类事项已在看板）
