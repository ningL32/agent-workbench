# BRAINSTORM · 任务叙事线补全（多听记关联 / 多日报 / Gitea 成果归因）

> 2026-10-19 · 业主三问触发 · 状态：头脑风暴，未开工
> 统一视角：v1.7 时间轴是骨架，三问 = 三类缺失的节点类型。补齐后详情页 = 任务完整档案。

## Q1 一个任务关联多个听记

**现状**：候选卡 ← 单条纪要；origin 只记首次来源；分析时的查重提示词只用来「防重复建卡」，没用来「识别对已有任务的讨论」。

**设计**：
- 分析输出 schema 增加 `taskUpdates`：AI 查重时若发现纪要内容是对**已有任务**的讨论/进展/变更 → 产出「更新提案」而非新候选。提案含 {existingTaskId, quote, note, confidence}
- 收件箱出现两类卡：**新任务候选**（现有）/ **任务更新提案**（显示关联任务 + 原文引用）
- 更新提案确认后 → 往该任务事件流写 `type:"memo"` 节点（纪要标题 + 引用），`origin.relatedMemos[]` 追加——任务和听记天然 N:N
- 更新提案同样过人工闸门（与任务候选同规则）

**典型场景**：周一会上提出「接入 SSO」（创建），周三会跟进「SSO 联调遇阻」（更新提案 → 挂到 SSO 任务时间轴），周五 PR 合并（Gitea 节点）——三段叙事一条线。

## Q2 多日任务的日报

**现状**：没有日报载体；updatedAt 只反映最后动作；「干了几天、每天干了啥」无处可查。

**设计**：任务详情新增「日报」区块，按日条目（日期 + 内容 + 来源）。三个入口，由轻到重：
1. **手动**：详情页「写日报」按钮（默认当天，可补历史日期）
2. **半自动**：当日该任务有 Gitea 归因提交（见 Q3）→ 日报草稿预填「今日提交 X 次：…」，人补一句话即可
3. **AI 草稿**：Q1 的更新提案确认后自动生成当日日报节点（引用纪要原句）

数据：`data/task_diary.json` {taskId, date, content, source: manual|gitea|memo, refs[]}。成员进度「今日产出」可升级为日报+归因提交的合成口径。

## Q3 进行中任务关联 Gitea 成果

三层由浅到深：

| 层 | 机制 | 评价 |
|---|---|---|
| **L1 手动挂接** | 团队动态/网关动态里的任何 commit/PR → 「归属任务」按钮 → 选任务 → 事件流记 `artifact` 节点（url/kind/repo）；详情可手动添加成果链接 | 最稳，零约定成本，MVP 首选 |
| **L2 弱约定自动归因** | 分支命名约定 `task/<taskId>-<slug>`（建任务时一键复制建议分支名）+ 提交信息含任务号 `[#t-xxx]`；轮询扫描按**精确规则**归因 | 推行后日常零操作；规则精确无模糊误配 |
| **L3 语义匹配** | AI 按 diff 内容与任务 desc 匹配 | 成本高误配风险大，远期 |

误归因防护：L2 是精确规则（前缀/关键字）无模糊空间；归属错了可手动解除。

## 统一收益

三项补齐后：**成员进度「今日产出」从「按作者全局统计」升级为「按任务归因」**（X 提交 · Y PR 拆到任务上）；时间轴成为任务档案；误识率之外再多一个质量仪表——更新提案的采纳率。

## 分期建议

- **第一批**：Q1 更新提案 + Q3-L1 手动挂接（都长在收件箱/动态已有交互上，改动最小）
- **第二批**：Q2 日报（含 Gitea 预填）+ Q3-L2 分支约定与 `[#t-xxx]` 归因
- **第三批**：产出统计按任务归因重构、AI 日报草稿、更新提案采纳率仪表

## 开放问题（业主拍板）

1. 日报管理强度：进行中任务当天无日报 → 成员页标「今日未填」吗？（要不要做成轻管理）
2. 更新提案闸门：逐条确认（与任务候选一致），还是同会议同任务的多条更新自动合并为一条？
3. Q3-L2 分支约定能在团队推行吗？（涉及所有人建分支的习惯；推不动就只做 L1+提交关键字）
