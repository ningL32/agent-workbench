## 1. 目标与非目标

**目标**：每天 10–15 分钟，把知识库里的一两个概念**从"见过"推到"能讲、能追问、能迁移"**，并按遗忘曲线安排复习。

**非目标**（明确不做）：
- 不做知识库写入/摄入/整理——vault 只读，一个字节都不写（`raw/`、`wiki/`、`index.md`、`log.db` 全不碰）。
- 不做"刷卡片"式记忆（选择/填空）——那是背结论，不是懂原理。
- 不替代现有 opencode 每日一卡流水线，**只消费它的产物**（见 §3）。
- 不做多用户、不做云端同步（红线 7）。

## 2. 为什么这套能真的学会（每条机制对应一个动作）

| 学习科学机制 | 本方案里的动作 | 反例（现在做不到的） |
|---|---|---|
| 主动回忆（retrieval practice） | **开卷前先闭卷写**："关于 X 你现在能说出什么" | 先看卡再看答案 = 熟悉感冒充掌握 |
| 自我解释（self-explanation） | 费曼轮：**禁术语**讲给外行，AI 抠"你哪句是术语代替理解" | 复述原文 |
| 追问到根（elaborative interrogation） | 5-why：连问 5 层"为什么"，答不出就是没懂 | 记住结论 |
| 迁移检验（transfer） | 收尾必答："举一个知识库外的例子 / 反例" | 只会原场景 |
| 间隔（spacing） | 1/3/7/16/35 天阶梯，答错重置（§6） | 一次性看完 |
| 交错（interleaving） | 复习队列**混着**不同主题出，不按目录顺序 | 一次只啃一个主题 |
| 即时反馈 | AI 每次只给 3 条：讲对了什么 / 漏了什么 / 哪句是在背 | 无人批改 = 不知道自己假懂 |

**硬约束（"有效学习"的可验证定义）**：每个环节必须**提交文字答案**才能进下一步；跳过=本次不算数（不计入调度）。

## 4. 每日会话（核心流程）

一次会话 = **1 个新条目 + 最多 3 个到期复习**，硬上限 15 分钟。顺序固定：

```
① 开口（不看材料）
   系统问：「先别看资料。关于「<主题>」，你现在能说出什么？可以很短，但要说人话。」
   用户写 1–5 句 → 存为 recallAnswer（这一步是"测"，不是"学"）

② 喂料（才给材料）
   展示条目的 digest（≤400 字，来自 wiki 页/卡片，带出处路径），只展示这一次

③ 费曼轮
   系统：「合上材料，用给完全外行讲的方式讲一遍：不许用术语，必须有一个类比。」
   用户写 → AI 批改（§5.1）→ 返回：讲对的点 / 漏的点 / 术语替代处 + 追问 1 个

④ 5-why 轮
   系统按 §5.2 逐层追问，用户逐层答；连续两层答"不知道"或明显循环 → 停，直接给根因

⑤ 收尾（迁移题 + 自评）
   「举一个知识库之外的例子（或反例）。」→ 用户答 → 自评 0–3（§6）
   AI 综合给出"掌握度"建议值 + 明日复习点一句话
```

模式可拆：条目可标 `preferMode=feynman|why5`，但**都强制走 ①**（先测），费曼与 5-why 默认串联，时间不够时 v1 允许只跑 ③。

## 5. 提示词（引擎调用，一次一站，避免多轮烧钱）

引擎复用 `lib/analyze.js` 的 dsh CLI 调用方式（`resolveDshBin` + 超时 + 失败留痕），**每次会话固定 3 次调用**：

### 5.1 批改（费曼轮）

```
你是严格但克制的学习教练。材料如下（唯一依据，不得补充材料外知识）：
<material>…digest + 出处…</material>
学员的解释：<userText>
请只输出 JSON：
{"good":["讲对的点，≤3条"],"missing":["材料里关键但没讲到的点，≤3条"],
 "jargon":["哪句是用术语代替理解，≤2条，引用原句"],"misconception":["与材料相反的表述，没有则空"],
 "probe":"一个能暴露是否真懂的追问（一句话）",
 "level":0|1|2|3}
判定标准：0=跑题/空白；1=复述术语；2=用自己的话讲清且类比成立；3=还能指出边界或反例。
禁止编造材料里没有的内容；材料不足以判定时 level 返回 null 并说明。
```

### 5.2 五问（5-why）

```
基于材料，就「<主题>」生成一条 5-why 追问链，用于检验学员是否懂机理而不是结论。
要求：每一问都要能由上一答继续深挖；不得跳步到结论；第 5 问必须落到"约束/激励/成本"这类根因。
只输出 JSON：{"chain":["问1","问2","问3","问4","问5"],"root":"根因一句话","materialBoundary":"材料支持到第几层"}
运行时逐问展示，学员答完再出下一问；学员连续两层答不出 → 直接展示 root 并结束。
```

### 5.3 收尾评估（可选，若 5.1 已给 level 可跳过，省一次调用）

```
输入：recallAnswer、费曼轮 level、5why 答题情况、迁移题答案。
输出 JSON：{"level":0-3,"keep":["明天还要复习的点，≤2条"],"nextStep":"一句具体建议"}
```

## 6. 遗忘曲线与调度（SM-2 简化版）

每条目状态：`level(0-3)`、`intervalDays`、`lapses`、`dueAt`、`lastReviewedAt`。

| 本次掌握度 | 下次间隔 | 说明 |
|---|---|---|
| 0（空白/跑题） | 1 天 | 明日重来，`lapses+1` |
| 1（只会复述术语） | 1 天 | 明日换角度（变式题）再问 |
| 2（能讲清+类比成立） | 按阶梯升一级 | 1 → 3 → 7 → 16 → 35 天封顶 |
| 3（能迁移/指出边界） | 跳一级 | 新条目可直接从 3 天起 |

- **每日队列** = 到期条目（`dueAt ≤ 今天`）优先，最多 3 个；队列不足才补 1 个新条目（对齐 vault 题库"复习优先于新题"）。
- **交错**：同日多个到期条目按 `kind`/目录打散，不连续同一主题。
- **熔断**：同一条目 `lapses ≥ 3` → 停止自动出题，标 `needsRewrite`（说明材料讲不清或选题太大，该换素材/拆小）。
- **时间衰减**：条目 90 天未复习且 level ≤1 → 降为"重学"（下次按新条目处理）。

所有调度是**纯函数**（输入 item+本次评分+今天 → 输出新 item+下次 dueAt），可表驱动单测，不依赖时钟（注 `now`）。

## 7. 配置（设置页；未配置 = 功能不存在）

```json
"learn": {
  "enabled": false,                       // 总开关；false 时「学习」菜单不出现
  "root": "D:\\knowledge\\my-vault",      // 只读；必须是绝对路径且存在（示例路径，换成你的知识库根目录）
  "scope": ["wiki"],                      // 业主拍板=全 wiki；支持多目录与 "wiki/思维方法论" 这类子路径
  "exclude": [],                          // 排除子路径（全 wiki 起步的减压阀，命中即不进池子）
  "dailyNew": 1,
  "dailyReview": 3,
  "minutes": 15,
  "engine": { "mode": "dsh", "timeoutSec": 180 }
}
```

- 三处同步：`store.DEFAULT_CONFIG` + `mergeConfigDefaults` + `giteaClient.DEFAULTS`（AGENTS §2 纪律）。
- 路径校验：必须绝对路径、必须存在、必须含 `AGENTS.md` 且正文有 "LLM Wiki" 标记（防配错目录）；**只读**（代码里对该目录只有 `readFile/readdir/stat`，无写调用）。
- **全 wiki 的代价（如实登记）**：312 篇里混着漫剧模板、企微研究、项目审计等，条目质量参差。缓解 = `exclude` 减压阀 + 条目标 `needsRewrite` 后不再自动出题 + "学习库"页可手动剔除单个条目（**只改我们的 items.json，不动 vault**）。
- `scope: ["wiki"]` 只扫 `wiki/`，不扫 `raw/`（事实来源，太脏且不适合当教材）；历史卡片因位于 `wiki/学习卡片/` 自然被覆盖。

## 8. 数据模型（全在本仓 `data/learn/`，不进 vault）

| 文件 | 内容 |
|---|---|
| `items.json` | 学习条目：`{id, kind:'card'|'page', sourcePath, title, tags, digest, createdAt, state}` |
| `schedule.json` | `{itemId, level, intervalDays, lapses, dueAt, lastReviewedAt, needsRewrite}` |
| `sessions.json` | 会话流水：`{id, date, itemId, stage, turns[], result, costMs}`（turns 含每步用户原文与 AI 反馈） |
| `scan.json` | vault 只读索引缓存 `{path, mtime, size, title, tags, kind}`（TTL 1 天，手动重建） |

`items` 去重键 = `sourcePath`；同一路径内容变了（mtime）→ 更新 digest，保留调度状态。

## 9. 接口

| 端点 | 语义 |
|---|---|
| `GET /api/learn/status` | `{enabled, configured, rootOk, dueCount, newCount, todayDone, engineOk}` |
| `GET /api/learn/today` | 今日队列（到期优先 + 至多 1 新），不含材料正文 |
| `POST /api/learn/session` | `{itemId}` → 建会话，返回第 ① 步问题（**不含材料**） |
| `POST /api/learn/session/:id/turn` | `{stage, text}` → 返回下一阶段提示/材料/AI 反馈（stage ∈ recall|feynman|why5|transfer） |
| `POST /api/learn/session/:id/finish` | `{level?}` → 落调度、返回"明日复习点" |
| `POST /api/learn/scan` | 重建 vault 索引（只读扫描；返回条目数/耗时） |
| `GET /api/learn/items` | 条目列表（用于"学习库"页与手动选题） |

会话是**服务端状态**（存在 `sessions.json`），刷新页面不丢；同一 `itemId` 同日只建一个未完成会话（幂等）。

## 11. 失败与降级（红线 8：必须留痕）

| 情况 | 行为 |
|---|---|
| 根路径不存在/无标记 | `status.configured=false` + 卡片红字说明；菜单不出现 |
| 引擎不可用（dsh 找不到/超时） | **降级为纯自评模式**：跳过 AI 批改，用户自评 0–3；`sessions` 记 `degraded:true`，统计里单列 |
| 材料太短/主题过大 | 条目标 `needsRewrite`，不再自动出题（宁缺勿滥） |
| 会话中断 | 会话状态在磁盘，可续；同一 item 同日不会重复建 |
| vault 读取失败 | 单条目跳过并记 `lastError`，不拖垮队列 |

## 12. 验收（可量化）

1. **功能门**：`learn.enabled=false` 或 `root` 无效 → `GET /api/learn/status` 返回 `configured:false`，SPA 导航无「学习」；设为有效后刷新即出现（无需重启）。
2. **只读门**：单测断言 `learn` 模块对 `root` 只有读调用（用注入 fs 观测写/删调用数必须为 0）；跑完一次完整会话后 vault 目录 mtime 不变。
3. **先测门**：`POST /session` 的响应里**不得包含材料正文**（断言 digest 不在返回体），必须先提交 recall 才返回材料。
4. **调度门**（表驱动）：level 0/1 → 明日；2 → 1→3→7→16→35；3 → 跳级；lapses≥3 → needsRewrite；90 天衰减。
5. **引擎门**：`fetcher/executor` 注入缝，单测零真实调用；引擎失败 → 会话标 degraded 且可完成。
6. **幂等门**：同日同 item 重复 `POST /session` 返回同一会话 id。
7. 全量 `node --test` 保持绿（当前 430）。

## 16.5 学习单元：原子知识点（v2.9.51 修订）
页面 ≠ 知识点。v1 以页面为条目，出题必然宽泛（"某方案横向对比"这种没法 5-why）。现行模型：
- **页面**（`pages.json`）只是素材来源；**知识点**（`items.json` v2）才是学习与调度单元，形如
  `{term, definition(≤60字), why(≤40字), sourcePath, pageTitle}`，id=`C-<sha1(page#term)>`。
- 抽取按需触发：未学知识点 <3 时挑一页未抽过的页面调一次引擎（`buildConceptPrompt`），抽完打 `conceptsAt`；
  页面 mtime 变了就清标记重抽。**扫描本身不调引擎**（312 页 × 每页一次会白烧钱）。
- 题面必须点名 `term`：先测「**<term>** 是什么」→ 费曼「给外行解释，不许用该术语或同义黑话」→
  5-why「围绕这个知识点追到根因」→ 迁移「哪里用得上、什么条件下不成立」。
- 批改提示词要求"学员讲别的话题（哪怕讲得对）→ level 0 并指出跑题"。

规则：①只收**不随时间快速过期**的硬概念（版本号/榜单/参数推荐不进）；②物化幂等（只补缺，不动已有调度），
scan 后与出题前各补一次；③混排——单日先知识库、双日先内置主题，各出 1 条；④`learn.seeds=[]` = 只用知识库；
⑤设 `learn.seeds` 时做白名单校验，未知主题返回 400 并列出可选值。

## 16.7 课程快照适配（v2.9.54）

把第三方课程仓（如 aieng 全仓快照）接进学习流时，`scope` 指向课程目录即可，但扫描器会做三件事：
①跳过 `README.md`（阶段/课级索引）；②跳过 `outputs/` 目录（课级产出物）；③跳过 `en.md`（中文版 `docs/zh.md` 已单独成条）。
另外扫描时抓 h2/h3 小节标题（≤12 条）随页面入索引，抽知识点时一起喂模型——长文里"小节名"比"前 400 字"更能定位该抽什么。
示例：aieng 阶段 14 第 1 课 → 8 个知识点（ReAct 循环 / Thought / Action / Observation / 工具注册表 / 停止条件 / 原生推理…）。

## 16.8 先测只用于复习（v2.9.57 修正）

v1 对所有条目都"先测（不给材料）"，对**全新知识点**是设计错误：检索练习的前提是"有部分记忆可提取"，
纯新内容先测只会卡住人。现行规则：

| 入口 | 判定 | 首步 | 材料 |
|---|---|---|---|
| 复习 | 该知识点在 `schedule.json` 里有记录 | `recall` 先测 | **不给**（提交后才给） |
| 新学 | 没有调度记录 | `study` 读材料 | **建会话即给**，题面"读完用一句话概括" |

每日队列口径（v2.9.61）：**到期条数（≤dailyReview）+ 新题条数（≤dailyNew）并行**。v1 写成"到期为空才补新题"，与设置里的「每日 N 新题」冲突——只要有一条到期，当天就只剩一条。
两种入口之后都进费曼讲解 → 五问 → 迁移，"必须自己输出"的原则不变。
旧版本建的 `recall` 会话在恢复时会自动补材料（`isReview !== true` 判定）。

## 17.5 别人怎么接入（初始化向导，v2.9.55）

**任何 Markdown 库都能用**，不要求 LLM Wiki 规范：

1. 打开「学习」→ 未配置时直接是向导：填库目录（绝对路径）→ 点「探测」；
2. 探测结果（只读）：库类型（llm-wiki / 普通 Markdown）、可学文档数、会自动跳过的数量（`_` 前缀 / README / outputs / en.md）、顶层目录分布；
3. 勾选学习范围（默认全选有内容的顶层目录；也可在设置里改 `scope`/`exclude`）；
4. 「开始初始化」→ 落盘配置 + 建索引 + **试抽一页**给出 6 个知识点预览（预览**不落库**，确认后才开始用）；
5. 之后每天按 `dailyNew` 出知识点，复习按 1/3/7/16/35 天阶梯。

API：`POST /api/learn/probe {root}`（只读）、`POST /api/learn/init {root, scope?, exclude?, dailyNew?, sample?}`。
校验口径：绝对路径 + 存在 + 目录即可；`AGENTS.md` 里的 LLM Wiki 标记只影响 `flavor` 与提示文案。

## 17.6 导入器：没有 Markdown 也能学（v2.9.56）

很多人手里是 PDF/Word/网页，不是 md。导入器把它们转成本地学习资料（**不写用户知识库**）：

| 格式 | 实现 | 可靠性 |
|---|---|---|
| `.md` / `.txt` | 直读 | 高 |
| `.html` / `.htm` | 去 script/style、块级标签转 md、解实体 | 高 |
| `.docx` | 自写 zip 解析（中央目录 + `inflateRawSync`）+ 抽 `w:t` | 高（标准 docx） |
| `.pdf` | 解 `FlateDecode` 流 + 抓 `Tj/TJ` 操作符 | **有限**：文字版 PDF 多数可用；扫描件 / 子集字体（很多中文电子书）抽不出字 → **明确报错**，不塞乱码 |

落点 `data/learn/imports/<slug>.md`，页面索引 `import:<slug>`；重扫知识库时这些页面会被保留。
接口：`POST /api/learn/import/preview {path}`、`POST /api/learn/import {path}`。
失败样本（真机）：3.8MB PDF 电子书 → `PDF 没抽出可用文本（扫描件或子集字体编码）`。要覆盖这类，
只能上 OCR 或外部转换工具（如 `pdftotext`），属于**可选外部依赖**，不在本插件打包范围内。

## 17. 运行前提（2026-10-31 真机实测）

1. **引擎优先级（v2.9.47 起）**：`learn.engine.mode=auto`（默认）→ 优先用**宿主 llm 服务**（进程内、用当前 profile 默认模型，桌面端即 DeepSeek 账号通道）；拿不到服务才回落 spawn 的 `dsh --profile headless`。下面的 GLM 坑只在回落路径/`mode=dsh` 时才有意义。
   **AI 批改依赖 headless profile 的模型凭据**：`~/.dsh/profiles/headless/cordis.patch.yml` 用
   `provider: zai-coding-cn` + `apiKeyEnv: GLM_API_KEY`。该键在 User 环境变量里已存在，
   但**DSH 进程必须从带有它的环境启动**（实测：从本会话工具启的实例没继承 → 批改失败）。
   缺失时按设计降级：`degraded:true`、会话继续、界面标「本次无 AI 批改」。
2. **延迟（v2.9.48 后）**：两段调用已并行、并把 `reasoningEffort` 压到 `low`——真机三档：`high` 串行 187s → `low` 并行 89.4s → **`off` 并行 3.5s**（桌面 DeepSeek 通道实测；`off` 下批改与五问链质量仍可用，故默认取 `off`）。仍受模型本身速度约束，界面有「AI 批改中… Ns」计时。**旧口径**：一次批改 + 5why 链约 137 秒（glm-5.3-flash + high）。
   界面已给「AI 批改中… Ns」计时；单次会话共 2 次引擎调用。要更快只能降 `reasoningEffort`
   （profile 级配置，需业主点头，不在本模块内改）。
3. **同一引擎也是雷达分析的引擎**：headless 缺凭据时，任务雷达的「AI 拆解」同样会失败——
   这条记录在这里，避免以后再当成雷达自身 bug 排查。
